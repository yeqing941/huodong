# 游戏活动参考库 PRD 1.0

- **版本**：v1.0
- **创建日期**：2026-10-17
- **文档性质**：产品需求文档
- **目标读者**：产品、设计、研发、测试、运营
- **来源**：基于《游戏活动参考库》原始 PRD，补充运营爬虫操作权与 AI 待打标初审权

## 1. 背景与目标

### 1.1 用户问题

产品运营团队在设计商业化活动时，需要频繁参考其他游戏的活动界面和玩法。现有资料分散在 Game UI、游戏官网、TapTap、社区帖子等渠道，存在以下问题：

- 同类活动需要重复搜索，检索效率低；
- 活动形式缺乏体系化标签，难以精准筛选；
- 缺少按活动形式横向比较多个游戏活动的统一入口；
- 新发现的活动无法持续沉淀，团队知识复用率低。

### 1.2 产品目标

建设一个面向游戏产品运营团队的竞品活动界面参考库，实现：

1. 按活动形式、游戏类型、游戏名称快速筛选活动参考；
2. 以截图卡片和详情页为核心，支持浏览、收藏和横向参考；
3. 通过定时爬虫和手动触发持续采集外部活动数据；
4. 通过 AI 自动打标和人工审核保障数据可检索性；
5. 在限制批量搬运、批量导出和破坏性操作的前提下，保证数据可恢复、可追溯。

### 1.3 成功标准

- 运营人员在 30 秒内定位某一活动形式下的竞品参考集合；
- 每条正式活动记录包含至少 1 张截图、活动名称、游戏名称、游戏类型和活动形式标签；
- 爬虫失败、AI 打标失败和人工录入失败均可被发现、重试或修正；
- 运营可独立完成已配置爬虫的手动触发、结果处理和 AI 标签初审；
- 超级管理员保留爬虫配置、标签树、用户和最终数据质量控制权。

## 2. 产品范围

### 2.1 P0 必须实现

- 登录与三档角色权限：普通用户、运营、超级管理员；
- 活动形式标签树浏览与多维组合筛选；
- 活动卡片网格浏览和活动详情页；
- 收藏与我的收藏；
- 手动录入活动；
- 定时爬虫、运营/管理员手动触发爬虫；
- 爬虫任务结果查看、失败重试和异常处理；
- AI 自动打标、运营初审、超级管理员最终修正；
- 标签树管理（超级管理员）；
- 操作日志、软删除、防批量导出和接口限流。

### 2.2 P1 增强功能

- 按游戏类型聚合浏览；
- 最近 7 天新入库活动时间线；
- 运营自定义私有子标签；
- 最多 4 张截图并排对比。

### 2.3 明确不做

- 社区评论、点赞、分享；
- 竞品活动效果数据，如 DAU、付费转化率；
- PDF 或批量图片导出；
- 全库数据 dump 接口；
- 移动端 App，P0 仅建设响应式 Web。

## 3. 用户角色与权限

### 3.1 角色定义

| 角色 | 描述 | 核心职责 |
|---|---|---|
| 普通用户 | 团队成员 | 浏览、筛选、查看详情、收藏 |
| 运营 | 负责活动内容和采集任务日常处理 | 手动录入、触发已配置爬虫、处理爬虫结果、AI 标签初审 |
| 超级管理员 | 系统和数据质量负责人 | 用户、标签树、爬虫配置、最终标签修正和破坏性操作管理 |

### 3.2 权限矩阵

| 操作 | 普通用户 | 运营 | 超级管理员 |
|---|---:|---:|---:|
| 浏览、筛选活动 | ✅ | ✅ | ✅ |
| 收藏活动 | ✅ | ✅ | ✅ |
| 手动录入活动 | ❌ | ✅ | ✅ |
| 批量录入活动 | ❌ | ✅ | ✅ |
| 修改自己录入的活动 | ❌ | ✅ | ✅ |
| 修改他人录入的活动 | ❌ | ❌ | ✅ |
| 手动触发已配置爬虫 | ❌ | ✅ | ✅ |
| 查看爬虫任务结果 | ❌ | ✅ | ✅ |
| 查看失败记录 | ❌ | ✅ | ✅ |
| 重试失败任务/单条失败记录 | ❌ | ✅ | ✅ |
| 处理 AI 待打标队列 | ❌ | ✅初审 | ✅最终修正 |
| 修改任意活动标签 | ❌ | ❌ | ✅ |
| 管理爬虫来源、规则和频率 | ❌ | ❌ | ✅ |
| 管理标签树 | ❌ | ❌ | ✅ |
| 管理用户和角色 | ❌ | ❌ | ✅ |

## 4. 核心业务流程

### 4.1 浏览流程

登录 → 选择活动形式标签 → 叠加游戏类型/游戏名称筛选 → 浏览卡片 → 查看详情大图 → 收藏或查看相关活动。

### 4.2 爬虫流程

定时任务或运营/管理员手动触发 → 读取已配置来源规则 → 抓取活动页面和截图 → 去重 → AI 打标 → 按置信度进入正式库或待审核队列 → 运营初审 → 超级管理员确认/修正 → 正式入库。

### 4.3 手动录入流程

运营/管理员填写活动信息 → 上传至少 1 张截图 → 选择至少 1 个活动形式标签 → 保存 → 直接进入正式库，不经过 AI 队列。

### 4.4 活动编辑流程

运营编辑自己录入的活动，超级管理员可编辑任意活动 → 表单回填原活动字段、游戏类型和已有标签 → 修改并保存 → 返回详情页并记录操作日志。

### 4.5 批量录入流程

运营/管理员进入活动录入页的批量录入页签 → 选择 CSV/Excel 文件 → 查看预览和问题记录 → 导入有效记录 → 新记录进入正式库并记录导入结果。原型阶段使用预设导入结果，不实现真实文件解析。

### 4.6 活动归档流程

超级管理员在活动详情页选择归档 → 二次确认归档原因 → 活动状态变为 archived 并从正常活动库隐藏 → 记录操作日志 → 超级管理员可恢复。

### 4.7 标签与游戏类型配置流程

超级管理员在标签树管理页选择活动形式标签或游戏类型页签 → 新增/编辑/排序/停用配置 → 新配置同步到活动录入和活动筛选选项。

## 5. 功能需求

### 5.1 标签树导航与筛选

**FR-01 标签树导航**

- 首页展示活动形式标签树，支持展开/折叠；
- 点击一级标签时，展示该标签及子标签命中的活动；
- 标签显示命中数量；
- P0 标签树最多支持 3 层；一级标签由团队预设，超级管理员不可删除但可调整顺序。

**FR-02 多维筛选**

- 支持活动形式、游戏类型、游戏名称模糊搜索组合筛选；
- 任一条件变化后即时刷新，无需额外点击搜索；
- 展示当前筛选条件，支持单项移除和一键清空。

**FR-03 排序**

- 默认按最近爬取/入库时间倒序；
- 支持按游戏名称 A-Z 排序。

### 5.2 活动浏览与详情

**FR-04 活动卡片**

卡片展示活动截图缩略图、游戏名称、游戏类型、活动名称、最多 2 个标签和剩余标签数量。点击卡片进入详情页，支持收藏。

**FR-05 活动详情**

- 展示全尺寸截图；多图支持切换和缩略图导航；
- 展示游戏名称、游戏类型、活动名称、活动时间、标签、来源 URL、采集方式和入库时间；
- 来源 URL 在新窗口打开；
- 展示同标签相关活动，最多 8 条。

**FR-06 收藏**

- 卡片和详情页均可收藏/取消收藏；
- “我的收藏”按最近收藏时间倒序；
- 收藏列表仅本人可见。

### 5.3 爬虫与任务管理（含运营操作权限）

**FR-07 定时爬虫**

- 系统按超级管理员配置的来源、游戏范围和频率执行；
- 爬取任务与主应用隔离；
- 失败任务不影响已有活动数据；
- 任务结果进入统一任务中心。

**FR-08 手动触发爬虫**

运营和超级管理员可从任务中心选择已配置的来源站点和游戏，发起单次爬取。运营不可创建或修改爬虫配置。

任务详情至少展示：任务状态、开始/结束时间、来源、游戏范围、新增数量、重复数量、失败数量、待打标数量和错误摘要。

**FR-09 爬虫结果处理**

- 运营和超级管理员可查看任务结果；
- 可查看失败记录的 URL、失败原因和最近重试时间；
- 可重试失败任务或单条失败记录；
- 连续 3 次失败的站点自动暂停定时任务，并提醒超级管理员；
- 运营不可修改来源规则或频率。

**FR-10 手动录入与编辑**

运营和超级管理员可录入：游戏名称、游戏类型、活动名称、活动时间、活动截图、活动形式标签、来源 URL、描述。截图至少 1 张，标签至少 1 个。

- 运营可编辑自己录入的活动；超级管理员可编辑任意活动；
- 编辑时回填原有字段、已有标签和游戏类型；
- 支持取消已有标签、补充已有标签树中的标签和修改游戏类型；
- 保存后记录操作日志。

**FR-10A 批量录入**

运营和超级管理员可在活动录入页的批量录入页签选择 CSV/Excel 文件，查看预览、有效记录和问题记录，并导入有效记录。问题记录至少标记活动名称/游戏名称缺失、标签不存在、游戏类型不存在或已停用。P0 原型使用预设导入结果，不提供批量编辑、批量删除或批量导出。

### 5.4 AI 打标与人工审核

**FR-11 AI 自动打标**

- AI 仅从已定义标签树中选择 1–3 个标签，不得创建新标签；
- 返回候选标签、置信度和分析状态；
- 置信度低于 70%、返回多个冲突候选、无法识别或服务失败时进入待审核队列；
- AI 服务不可用时，原始爬取数据保留，状态为 pending_tagging。

**FR-12 运营初审**

运营可查看待审核队列中的截图、活动信息、AI 候选标签和置信度，并执行：

- 接受 AI 建议；
- 取消错误标签；
- 从已有标签树中补充标签；
- 标记为需要管理员确认；
- 将无法判断的记录退回或备注原因。

运营初审后记录进入 `pending_admin_review`，不可直接绕过管理员最终确认。

**FR-13 超级管理员最终审核**

超级管理员可确认运营初审结果、修改任意标签、处理 AI 失败记录，并将活动状态改为 active。审核记录保留操作人、时间、原标签、新标签和处理意见。

**FR-14 标签树与游戏类型管理**

超级管理员可新增一级、二级、三级标签、修改名称/说明/AI hints、调整顺序和合并重复标签。新增二级/三级标签时必须选择父级；标签树最多三层。删除标签前必须迁移该标签下所有活动；一级标签不可删除。

超级管理员可在同页“游戏类型”页签新增、编辑、排序、查看关联活动数量和停用游戏类型。已被活动使用的游戏类型不可直接删除，只能停用或迁移。停用类型不能用于新录入，历史活动保留原类型；活动筛选只展示启用类型。

**FR-14A 活动归档与恢复**

超级管理员可在活动详情页归档错误活动或污染源活动。归档需要二次确认和原因，状态变为 archived，从正常列表隐藏并记录操作日志。超级管理员可查看归档活动并恢复；不提供物理删除。

### 5.5 用户与账号

**FR-15 登录与账号管理**

- 登录方式待部署阶段确认，优先支持公司内部 SSO 或飞书登录；
- P0 可使用独立账号密码作为 fallback；
- 超级管理员可新增、停用用户和修改角色；
- 部署时内置 1 个超级管理员账号，首次登录需修改初始凭证。

## 6. 数据模型

### 6.1 活动记录 ACTIVITY

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | UUID | — | 系统生成 |
| source_url | URL | 是 | 原始活动页面地址 |
| source_site | 枚举 | 是 | game-ui、官方官网、官方社区、手动录入 |
| game_name | String | 是 | 游戏名称 |
| game_genre | 枚举 | 是 | 由超级管理员维护的启用游戏类型；历史记录可保留停用类型 |
| activity_name | String | 是 | 活动名称 |
| activity_start/end | Date | 否 | 活动时间 |
| screenshots | Image[] | 是 | 一张或多张截图 |
| tags | Tag[] | 是 | 至少一个活动形式标签 |
| description | Text | 否 | 活动简介 |
| status | 枚举 | — | pending_tagging、pending_admin_review、active、archived |
| created_at | Date | — | 创建时间 |
| created_by | User | — | 录入者或 system |

### 6.2 标签 TAG

包含 id、name、parent_id、level、description、ai_hints。标签树最多 3 层。

### 6.3 爬虫任务 CRAWL_TASK

包含 id、source_site、game_scope、trigger_type（scheduled/manual）、triggered_by、status、started_at、finished_at、new_count、duplicate_count、failed_count、pending_tagging_count、error_summary。

### 6.4 审核记录 REVIEW_LOG

包含 id、activity_id、reviewer、reviewer_role、action、before_tags、after_tags、comment、created_at。

## 7. 去重、异常与可恢复性

### 7.1 去重

以 `source_url + game_name + activity_name` 作为默认去重键。已存在记录跳过；若截图更新则更新 screenshots 和采集时间，并保留变更日志。

### 7.2 AI 异常

- 无法识别/空结果：进入待审核队列，原因标记为 ai_failed；
- 返回非标签树内容：忽略无效标签，仅保留有效候选；
- AI 服务不可用：保留原始数据，状态为 pending_tagging。

### 7.3 爬虫异常

- 404、超时、反爬拦截：记录站点、URL、错误类型和时间，任务标记 partial；
- 单站点失败不阻断其他站点；
- 连续 3 次失败自动暂停定时任务并通知超级管理员；
- 运营可重试任务或单条记录，但不可修改反爬策略和站点配置。

### 7.4 数据安全

- 不提供批量导出、批量下载和全库 dump；
- 不做技术性阻断浏览器原生单张保存；
- 删除统一采用 archived 软删除，超级管理员可恢复；
- 删除和配置变更需二次确认；
- 搜索和列表接口按 IP + 账号限流，防止脚本化遍历；
- 关键操作记录审计日志。

## 8. 页面与模块

1. 登录页；
2. 首页/活动浏览页：标签树、筛选栏、卡片网格、排序；
3. 活动详情页：大图、字段、收藏、相关活动；
4. 我的收藏页；
5. 活动录入页；
6. 爬虫任务中心：任务列表、任务详情、手动触发、失败重试；
7. AI 待审核队列：运营初审和管理员最终审核；
8. 标签树管理页：超级管理员；
9. 用户与权限管理页：超级管理员；
10. 操作日志页：超级管理员。

## 9. 验收标准

- 用户可按标签、游戏类型和游戏名称组合筛选，并即时看到结果；
- 活动卡片可进入详情，详情可查看多张截图和来源 URL；
- 三种角色按权限矩阵执行操作，越权请求在前端隐藏且后端拒绝；
- 运营可手动触发已配置爬虫、查看结果、重试失败记录；
- 运营可初审 AI 标签，但不能直接完成超级管理员最终确认；
- 超级管理员可管理爬虫配置、标签树、游戏类型、用户和任意活动；
- 活动编辑可回填并修改原有标签和游戏类型；
- 运营和超级管理员可使用批量录入页签导入有效记录并查看问题记录；
- 爬虫任务展示进度、失败 URL、失败原因，并支持单条失败记录重试；
- 爬虫、AI、录入失败均有状态、原因和可恢复路径；
- 删除为软删除，可恢复；不提供批量编辑、批量删除、批量导出和全库 dump；
- 关键权限、标签、游戏类型、归档和任务操作可查询审计日志。

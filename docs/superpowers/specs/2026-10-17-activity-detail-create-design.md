# 活动详情与新建活动设计

## 1. 目标

补齐活动参考库的两个前端业务闭环：

1. 用户从活动库进入活动详情，查看完整活动信息并进行收藏操作。
2. 运营和管理员创建活动，提交后进入活动详情页。

本阶段沿用现有 Django API、JWT 会话和 Element Plus，不引入新的状态管理或 UI 框架。

## 2. 范围

### 包含

- `/activities/:id` 活动详情路由和页面。
- `/activities/new` 新建活动路由和页面。
- 活动列表卡片进入详情。
- 详情页展示基本信息、时间、描述、标签、截图、来源和收藏状态。
- 新建表单动态加载游戏类型和启用标签。
- 新建表单提交活动名称、游戏名称、游戏类型、来源信息、描述、标签和截图路径。
- 运营、管理员访问新建页面；普通用户被路由守卫拒绝并回到活动库。
- 成功创建后跳转新活动详情页。

### 不包含

- 活动编辑。
- multipart 文件上传和图片裁剪。
- 三级标签管理界面。
- 活动审核、爬虫和审计功能。
- 后端数据模型和接口协议的大范围调整。

## 3. 页面与路由

### 活动详情页

路径：`/activities/:id`

页面结构：

- 顶部返回活动库按钮。
- 活动标题、游戏名称、游戏类型和状态。
- 活动时间区间。
- 标签列表。
- 活动描述。
- 截图画廊；无截图时显示明确空状态。
- 来源站点和可访问的来源链接。
- 收藏/取消收藏按钮。

加载时调用 `GET /api/v1/activities/:id`。加载失败显示统一错误提示并提供返回入口。收藏成功后只更新当前详情页状态，不重新加载整页。

### 新建活动页

路径：`/activities/new`

页面结构：

- 返回活动库按钮。
- 活动名称、游戏名称、来源 URL、来源站点、描述输入框。
- 游戏类型下拉框。
- 标签多选框。
- 截图路径输入框；至少填写一项。
- 提交和取消按钮。

页面进入时并行调用：

- `GET /api/v1/game-types`
- `GET /api/v1/tags`

提交调用 `POST /api/v1/activities`，请求体沿用当前后端接口字段：

```json
{
  "source_url": "...",
  "source_site": "manual",
  "game_name": "...",
  "game_type_id": "...",
  "activity_name": "...",
  "description": "...",
  "tag_ids": ["..."],
  "screenshot": "..."
}
```

创建成功后使用返回活动 ID 跳转 `/activities/:id`。后端错误直接转换为用户可读提示，不伪造成功状态。

## 4. 权限与数据流

- 路由元信息：详情页允许 `user/operator/admin`；新建页允许 `operator/admin`。
- 路由守卫负责未登录和角色级跳转。
- 后端现有 `activity:read` 和 `activity:write` 校验继续作为最终安全边界。
- 列表页仅对 `operator/admin` 显示“新增活动”按钮。
- 普通用户即使手动访问 `/activities/new`，也不能提交活动。

数据流：

```text
活动列表 → 点击卡片/标题 → 活动详情 API → 详情页
活动库 → 新增活动 → 类型/标签 API → 表单提交 → 创建 API → 新活动详情
```

## 5. 组件边界

- `ActivityDetailView.vue`：只负责详情数据加载、收藏交互和展示。
- `ActivityCreateView.vue`：只负责表单状态、选项加载、校验和提交。
- `ActivityLibraryView.vue`：负责列表筛选和入口跳转，不承载详情或创建逻辑。
- `router/index.ts`：注册路由和角色元信息。
- `types/api.ts`：补充游戏类型、标签和创建响应所需类型。

## 6. 错误处理

- API 请求错误统一通过现有 `ApiRequestError` 展示。
- 详情资源不存在或无权访问时显示错误提示并提供返回活动库操作。
- 新建表单提交前校验必填字段、游戏类型、至少一个标签和截图路径。
- 提交期间禁用按钮，避免重复创建。
- 取消不发送请求，直接返回活动库。

## 7. 测试与验收

### 自动验证

- `npm run type-check`
- `npm run build`
- Django 现有活动 API 和写入 API 测试全部通过。

### 浏览器验收

1. 普通用户登录后可打开活动库和详情页。
2. 普通用户可以收藏和取消收藏。
3. 普通用户访问新建路由会回到活动库。
4. 运营或管理员可以打开新建表单。
5. 新建表单能加载游戏类型和标签。
6. 缺少必填字段时不会提交。
7. 创建成功后跳转到新活动详情页并显示提交内容。
8. 刷新详情页后仍能通过 API 正常加载。

## 8. 实施约束

- 优先复用现有 API 和页面样式。
- 不在本阶段实现图片文件上传；截图字段使用 URL 或 Django 媒体路径字符串。
- 不修改登录、JWT 和现有后端权限实现，除非验证发现接口无法支持本设计。
